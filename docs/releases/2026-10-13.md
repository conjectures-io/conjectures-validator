# October 13 release handoff — prepared, not published

The release spans validator #124, web #121, and the already prepared tasks #18. Nothing in
this checklist is a production action until the owner authorizes launch. Keep the existing
production intake and task selection unchanged during preparation.

## Included

- New reward targets store a 1/40 starting share; existing rows retain 1/20. Both retain the
  15-day ramp to 1/8. Chat-log requirements apply only to the new policy.
- Private log deposits, review, forfeiture, earlier-proof claims, v8 submission terms, and an
  auditable correction path for the intake opening/cutoff.
- Taostats v1, payout cancellation and prior-public-proof fixes from the combined release.
- Collatz statements/audit and test-only previews. No Collatz or packing target activation.
- Mathlib adapter-2 support with legacy byte preservation and an explicit registry upgrade
  flag. Default incremental publication preserves existing headers; no task IDs are rotated.
- V048: historical bonus reservations and finalized payment records, private buyer agreements,
  consent, download audit and takedown tracking. Signing/payment execution and contacting
  buyers remain manual, documented operator steps.
- Publication fixtures reflect the Wilf e4 hold: 274 active targets, 548 active versions;
  historical research activation decisions remain preserved, with current holds applied.
- V049: optional supporting PDFs on the submission form and account page (three per submission,
  20 MiB each). Reviewers can read them before approval; public result and proof pages display
  them only after verification and approval. Authors can remove attachments independently.

   and daily/after-correction review of the buyer takedown queue. Follow

## Pause/rollback

Pause new intake if a check fails; do not delete consent, payment, export or cutoff records.
After V046/new-policy work exists, do not run an older payout/API binary. Roll forward with a
reviewed correction. Preserve accepted quotes, historical bundles and all finalized chain
observations. A database cancellation never recalls a signed or pending multisig transfer.

The watcher also needs EXECUTE on `public.trajectory_bonus_oldest_pending(text,text)` under
the same trusted owner with SELECT on `trajectory_payments`. This opens chain tracking when a
historical bonus is the only outstanding obligation.
